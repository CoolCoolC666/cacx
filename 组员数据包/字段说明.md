## 二、⚠️ 范围规则（重要，务必读懂）

老师的要求分两层，**两层范围不一样**：

| | 范围 | 原因 |
|---|---|---|
| **网站** | **不裁剪，2024 年以来全量 4433 篇** | 网站支持任意站点/栏目/时间筛选，裁了是倒退 |

**所以本数据包给的是 2024 年以来的全量**（两站 25 个栏目、4433 篇），
既够你们横向比较选栏目，也保证**投票结果出来后不用重新导数据**。

> 4433 篇里 **4432 篇有正文**，另 1 篇正文抓取为空（`content_empty=1`）。
> 做关系抽取/检索时按 4432 口径，别让那 1 篇空正文混进统计分母。

## 三、报告分析样本：目前只有 2 个可行窗口

老师要 300-500 篇。我们把每个栏目在两个时间窗下的篇数都算了一遍，
结果是——**2024+ 全量里没有任何栏目天然落在 300-500 区间**，
所以分析样本必须 = **栏目 + 时间窗**。只有这两个组合达标：

| 选项 | 站点 | 栏目 | 时间窗 | 篇数 | 联合发文类 |
|---|---|---|---|---|---|
| **A** | 中国网信办 cac | 网信要闻 | 2024-01-01 ~ 2025-12-31 | **475** | 39 篇 |
| **B** | 浙江网信网 zjwx | 网信要闻 | 2024-01-01 ~ 2025-12-31 | **327** | 30 篇 |

### 两个选项的实际差别

- **A（中央网信办 475 篇）**：权责边界的分析主体就是它，讲的就是它的角色；
  联合发文线索更多（39 篇）；数据量大，适合做细粒度统计。
- **B（浙江网信网 327 篇）**：地方样本，能讲「地方网信办在治理中怎么做」，
  且天然能做「浙江对照」——中央 vs 地方对比是老师标注的选做加分项。

> **选哪个由小组投票决定**，不由技术方指定。
> 提示词 `组员对接/00-选栏目投票.md` 会带你们走这个流程。

## 四、表结构

库只有一张有数据的表 `articles`（其余是空壳，方便 join）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER | 主键，回溯原文时用它 |
| `site` | TEXT | `cac` / `zjwx` |
| `site_name` | TEXT | 中国网信办 / 浙江网信网 |
| `column_code` | TEXT | 栏目代码 |
| `column_name` | TEXT | 网信要闻 / 治理监管 / 地方网信 … |
| `title` | TEXT | 标题 |
| `pub_date` / `pub_day` | TEXT | 发布日期，`pub_day` 是 YYYY-MM-DD（**时间统计用这个**） |
| `year` / `month` | TEXT | 年份 / 月份 |
| `url` | TEXT | **原文链接**——「点边看来源」要用 |
| `source_text` | TEXT | 页面上标注的来源（⚠ 多数是「新华社」等媒体名，**不是发文机关**） |
| `chars` | INTEGER | 正文字数 |
| `content_text` | TEXT | **正文全文，纯文本**——关系抽取的输入 |
| `content_html` | TEXT | 正文 HTML |
| `content_empty` | INTEGER | 1 = 正文抓取为空 |
| `first_seen` / `synced_at` | TEXT | 抓取时间 |
| `body_hash` | TEXT | 正文规范化指纹（去空白后取哈希）。**同一篇文章发在多个栏目时 URL 不同但它相同**，用它才能查出「一文多栏目发」。短的正文（<100 字）留空 |

已建索引：`site+pub_day`、`column_name`、`pub_day`、`site+column_name`

### ⚠️ 一个必须知道的坑

**库里没有「发文机关」字段。**

`source_text` 实测样例是 `新华社`、`浙江网信网`、`经济日报` 这类**媒体报道来源**，
**不是发文单位**。

所以「哪些部门常和网信办联合发文」这件事：
- **不能**靠现成字段，**必须**从 `title` + `content_text` 开头抽取
- 两份文件用的是**两级口径**，数字对不上是正常的，别当成 bug：
  - `联合发文线索.csv` 用**宽**口径（标题含 联合/印发/会同/**联发/共同**），共 **221 条**
    —— 故意放宽召回，交人去筛
  - `栏目候选清单.csv` 的「联合发文类」两列用**窄**口径（标题含 联合/印发/会同），
    只数强信号。所以按栏目统计线索表会得到比清单更大的数（旧包也是这个关系：222 与 168）
- 「疑似联合机关」由 `cacx/extract.py` 的 `_org_mentions()` 从正文抽出（与主库抽取**同源**，
  你可以自己复算），但仍是**机器粗抓**，**一定要人工复核**，别直接当结论用

> **口径变更记录**：
>
> **（2026-10-15）增量同步后重新出包**：主库全量 **28919 → 28917 篇**
> （浙江站「一文多栏目发」又混进 2 行重复，已清），2024+ **4416 → 4433 篇**，
> 有正文 **4432 篇**。**A/B 两个窗口的 475/327 篇与 39/30 篇联合发文未变**，
> 线索表仍是 221 条（214 条能抽出至少一个机关）。栏目数仍是 25 个。
>
> **（2026-10-13）**：
> ① 语料去掉了「一文多栏目发」的重复行，2024 年以来全量 **4519 → 4416 篇**；
>    A/B 两个窗口的 **475/327 篇与 39/30 篇联合发文一个都没变**（被删的重复恰好不在这些栏目窗口里），
>    只有线索表 222 → **221 条**。
> ② 「疑似联合机关」这一列换了抽取函数：上一版用的是一套已丢失的粗糙正则，
>    产出过 `部`、`部 / 中央网信办` 这种残缺词和大量空值；现在改用与主库同源的
>    `_org_mentions()`，**取值会与旧版不同**，但 221 条里 214 条能抽出至少一个机关
>    （旧版空值更多）。筛选口径本身两级都未改动。

## 五、常用查询

```sql
-- 选项 A 的分析样本（475 篇）
SELECT * FROM articles
 WHERE site='cac' AND column_name='网信要闻'
   AND pub_day>='2024-01-01' AND pub_day<='2025-12-31';

-- 选项 B 的分析样本（327 篇）
SELECT * FROM articles
 WHERE site='zjwx' AND column_name='网信要闻'
   AND pub_day>='2024-01-01' AND pub_day<='2025-12-31';

-- 按月统计发文量
SELECT substr(pub_day,1,7) ym, COUNT(*) n FROM articles
 WHERE site='cac' AND pub_day>='2024-01-01' AND pub_day<='2025-12-31'
 GROUP BY ym ORDER BY ym;

-- 正文为空的（抽取时要跳过）
SELECT COUNT(*) FROM articles WHERE COALESCE(content_empty,0)=1;

-- 正文太短的（规则抽不出关系）
SELECT COUNT(*) FROM articles WHERE COALESCE(chars,0)<200;
```
