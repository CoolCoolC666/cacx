## 你有两条路，优先第一条

### 路线 A：连上 cacx 的 MCP（推荐）

**怎么连**：在你智能体软件的 MCP 配置里加一段（`cwd` 改成你解压的目录）：

```json
{"mcpServers": {"cacx": {
  "command": "python", "args": ["-m", "cacx.mcp_server"],
  "cwd": "D:\\cacx-分发版-20261012"}}}
```

连上后一共有 22 个工具，你只需要下面这几个。

我们把取样、机构挖掘、实体关系写入都做成了 MCP 工具，
你**直接调工具就行，不用自己写解析代码**：

```
1. cacx_sample_options(date_from="2024-01-01", date_to="2099-12-31")
   → 看有哪些栏目可配

2. cacx_sample(column="<栏目>", limit=500, strategy="stratified")
   → 拿到样本。它会返回 years_taken，确认每年都有篇数

3. cacx_mine_orgs(column="<栏目>", limit=3000, min_count=3, merge=true)
   → 机构候选词（已按年份分层 + 归并同一机构的多种写法）
   ⚠️ 这是**候选**，不是结论。要人工/智能体复核哪些是真发文机关。

4. cacx_get_article(id) 逐篇取正文

5. cacx_put_entities(rows=[...])     写实体
   cacx_put_relations(rows=[...])    写关系

6. cacx_graph() / cacx_graph_stats()  出图谱、看证据覆盖率
```

**为什么推荐这条**：网站已经能展示「点一条关系 → 看到原文句子和链接」，
你写入 MCP 之后，**图谱是现成的**，不用自己再造可视化。

**MCP 写入的两条硬要求**（工具会拒绝，不接受就没写进去）：

- **每条实体/关系都必须带 `article_id`**（出处文章）。
  没有出处的关系在图谱上是无法验证的孤证，答辩时一问就塌。
- **每条关系都要带 `evidence`**（原文片段）。

写入是**幂等**的：同一篇的同一实体重复提交只更新证据，不产生重复行。
所以重跑一遍不会把图谱撑成双倍。

那就走原来的方式，最终仍要交 CSV（下游要读的是数据本身）。

## 背景（必读，不要跳过）

- 课程：网络舆情分析与监测
- 数据来源：中国网信办（cac.gov.cn）、浙江网信网（zjwx.gov.cn）**公开**文章
- 分发版数据库含**全量历史 2.8 万+ 篇**；**2024 年以来共 4416 篇**（两站 25 个栏目），
  样本配置器默认框住的就是 2024 年以来这批
- 报告只分析投票定下的那**一个**栏目 + 时间窗 + 篇数上限
- 这批数据仅供**课程作业与学习研究**使用，著作权归原作者与原网站

## 四类实体（老师指定的）

| 类别 | 说明 | 例子 |
|---|---|---|
| **机构** | 发文/执行/协同的政府部门、组织 | 中央网信办、公安部、市场监管总局 |
| **政策** | 法律法规、规划、意见、办法、通知 | 《网络安全法》《XX行动计划》 |
| **治理问题** | 文章针对的负面/待治理的社会问题 | 网络谣言、未成年人沉迷、虚假信息 |
| **措施** | 治理动作与手段 | 开展专项行动、约谈平台、处罚、下架 APP |

> MCP 里对应的 `type` 取值是：`org` / `policy` / `problem` / `measure`
> （工具会拒绝第五种取值，报错信息里会列出可选值）

## 需要抽的关系（老师点名的四类）

| 关系 | 问的是什么 | 边的方向 | MCP `rel_type` |
|---|---|---|---|
| `发布` | **谁**发布了这篇/这项内容 | 机构 → 政策 | `issue` |
| `针对` | 机构针对**什么问题** | 机构 → 治理问题 | `target` |
| `采取` | 采取了**什么措施** | 机构 → 措施 | `adopt` |
| `联合发文` | **和谁**一起发的 | 机构 → 机构 | `joint_issue` |

> 关系类型没有强制枚举，你可以按分析需要加
> （如 `regulate` 监管、`cite` 引用、`implement` 落实），但要在 README 里说明。

### 两个 CSV 的列定义

**`entities.csv`**

| 列 | 说明 |
|---|---|
| `entity_id` | 唯一编号，如 `E0001` |
| `entity_name` | 实体名称（**用原文里的写法**，不要自己改称谓） |
| `entity_type` | 只能是 `机构` / `政策` / `治理问题` / `措施` 四选一 |
| `mention_count` | 在样本里出现了多少次 |
| `first_seen` | 最早出现的日期 |

**`relations.csv`** — **这是老师最看重的文件。**

| 列 | 说明 |
|---|---|
| `relation_id` | 唯一编号 |
| `relation_type` | `发布` / `针对` / `采取` / `联合发文`（或你自定义的） |
| `src_id` / `src_name` | 主体 → 对应 `entities.entity_id` |
| `dst_id` / `dst_name` | 客体 → 对应 `entities.entity_id` |
| `evidence_article_id` | 支撑这句的文章 id |
| `evidence_sentence` | **原文里那一句**（逐字照抄，不许改写、不许翻译） |
| `evidence_url` | 原文链接 |
| `confidence` | `高` / `中` / `低` |

> ⚠️ **`evidence_sentence` 是这个作业的命门。**
> 老师要求「点每条边能看到原文句子和来源链接」。
> 没有原文句子的关系等于没有证据，**宁可少抽，不可编造**。

## 执行要求

1. **先抽样 20 篇通读**，摸清这批文章的写法规律，再决定批量方案。
   直接上来就跑正则，大概率抽出一堆垃圾。

2. **正文太短的跳过**：`chars < 200` 的文章基本抽不出东西，记录下来即可。

3. **机构名要归并**：同一机构可能有多种写法（`中央网信办` / `国家互联网信息办公室` /
   `……公安部`）。不归并的话，合作网络会裂成一堆孤岛。
   走 MCP 的话 `cacx_mine_orgs(merge=true)` 已经帮你并了。

4. **覆盖率说明**：不必强行覆盖样本里的每一篇。
   抽 150 篇以上、关系总数 300 条以上，就是合格。
   **质量比数量重要**——老师会点开边看原文，抽错一条就露馅。

5. **中文 CSV**：编码用 **UTF-8 with BOM**（Excel 双击才不乱码）。
   Python 里就是 `open(..., encoding='utf-8-sig', newline='')`

6. **诚实标注**：机器抽的和人工复核的要分开说。
   在 README 里写清楚比例。老师问起来，你答得上来。

## 不要做的事

- ❌ 不要自己编造、改写、润色「原文句子」
- ❌ 不要把推测当成事实写进 CSV
- ❌ 不要**只**交 Python 脚本了事——下游要读的是**数据文件本身**
- ✅ 脚本 / 提示词 / 工作流**可以一并交**，它们对后续接手的智能体很有价值，
  但必须和 CSV 放在一起，不能用脚本代替 CSV
- ❌ 不要**漏掉 `article_id`**。没有出处的关系进不了图谱回溯，等于白抽
- ❌ 不要试图一次抽完全部样本然后交一堆未复核的脏数据
