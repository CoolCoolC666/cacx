## 一、为什么这么拆

老师要的东西表面上是一个网站，实际上是**七件互不相同的东西**：
数据、关系、图谱、机构、时间、报告、界面。

拆分的原则是**按交付物拆，不按技术模块拆**：
每人负责一件**最终要出现在作业里的东西**，边界清楚、互不重叠、好验收。
按模块拆的话，每个人都在做「一半」，最后谁也说不清自己那块做完了没有。

⚠️ **有一个环节必须最先启动**——见下面的「依赖链」。

## 二、⚠️ 最关键的一件事：先投票定样本口径

老师要「**任选一个栏目**，300-500 篇，2024 年以来」。

但我们把数据算完了：**2024 年以来 25 个栏目里，没有任何栏目天然落在 300-500 篇**。
最多的有 1639 篇，最少的只有 14 篇。

所以分析样本 = **栏目 + 时间窗 + 篇数上限** 三件事一起定：

- **时间窗给足**：`2024-01-01` ~ `2099-12-31`（2024 年至今，**含 2026 年**）
- **篇数用上限调节**：300 / 400 / 500 都行
- **抽样按年份分层**：保证区间内每年都有篇数

这样**任何一个栏目都能配出合规样本**，选择权才真正在小组手里。

⚠️ **别用「最近 N 篇」**：实测取最近 500 篇只覆盖 2025-03 之后，
**2024 整年丢失**，「发文量与主题随时间的变化」这条要求就作废了。

**这三个参数影响 R1/R3/R4/R5 全部四项任务。**
如果各人按不同口径干活，最后拼不到一起，成果作废。

所以流程必须是：**先投票 → 立刻广播 → 其他人才能开工**。

- 建议 **1 人**做 `00-选栏目投票.md`，**限时 1 天**
- 收到建议后群里投票，全员投票少数服从多数
- 结果**当天**把「栏目 + 区间 + 篇数上限」三项一起告知所有其他角色

### 怎么抽

连上 cacx MCP 的话一条命令就有（也可以在网站的「样本配置器」页点出来）：

```
cacx_sample(column="<栏目>", limit=500, strategy="stratified")
```

它会返回 `years_taken`，**确认每年都有篇数**再看后面。

## 七、怎么给组员发（钉钉流程，不走 GitHub）

### 一次性动作

1. 把 `组员数据包/` 整个文件夹压缩成 zip，**发给每一位组员**
   （46 MB，钉钉能直接传）
2. 把对应的 `01`-``06` 提示词**原文**发给对应的人

### 提示词怎么用

告诉组员：

> 把提示词**整段复制**给你自己用的智能体（豆包 / Kimi / DeepSeek / ChatGPT 都行），
> 然后**把数据包一起传给它**，让它按提示词干活。

组员不需要装 Python、不需要 GitHub、不需要碰原工程。

### 收作业

- 成果一律**通过钉钉收回**，zip 命名 `姓名-编号-任务名.zip`
- **不用 GitHub**，避免卡在注册和权限上
- 原工程在 GitHub 上只是**备份**，已经公开（MIT），随时可查
