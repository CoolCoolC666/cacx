## 技术要求（重点，省掉你的踩坑时间）

### ⚠️ 关于 npm：项目本体可以用，**交付的那一份不行**

技术方的**主工程允许用 React / Vue / Vite / npm**，
所以你写 React 组件、用 ECharts、跑 `npm run build` 都是合理的——
代码质量和可维护性更重要。

但**最终交回来的那一个文件必须能双击打开**。理由很实在：
关系图谱要贴进报告、要在课堂上投影、要能单独发给别人看，
对方机器上不会先 `npm install`。

所以两条路径都可以，**你选一条并说明理由**：

| 方案 | 做法 | 适用 |
|---|---|---|
| **A. 单文件**（推荐） | ECharts/D3 的单文件版本**内联进 HTML**，双击即开 | 交付用 |
| **B. 工程方案** | Vite + React 组件，源码可维护，`build` 产出一个自包含 HTML | 你想把源码一起交，作为工程的一部分 |

**方案 B 也不是不能交**，但必须额外交付一份**构建后的自包含 HTML**。
只交源码目录、让别人自己 build 起来才能看 —— **不合格**。

### 硬性要求（两条方案都适用）

1. **断网能打开**：库里必须内联，不能是 `<script src="https://cdn...">`。
   教室的网络状况不能假设。
2. **不要交只有依赖清单的目录**：交回来的东西必须是我能直接双击打开的。

### 图的交互细节（这些是加分项）

1. **节点按类型着色**：
   - 机构 = 蓝
   - 政策 = 紫
   - 治理问题 = 红
   - 措施 = 绿
   （自己定，但要**图上有图例**说明哪个颜色是什么）

2. **边的类型要能区分**：四种关系至少用不同线型或颜色。
   点击某类关系时，其他边变淡（聚焦），这样 200 条边的图才看得清。

3. **侧边栏内容**（点边后显示）：
   ```
   关系类型：针对
   中央网信办  →  网络谣言
   原文句子：「……（这里逐字显示 evidence_sentence）」
   来源文章：（标题，做成链接可点）
   [打开原文 ↗]
   ```

4. **规模控制**：如果关系超过 300 条，默认只画 **出现频次 Top 60** 的节点，
   其余折叠成「显示更多」。全画出来是没法看的。
