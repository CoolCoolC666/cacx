## 第一部分：发文量（客观，容易）

按月统计：

```sql
SELECT substr(pub_day,1,7) ym, COUNT(*) n
  FROM articles
 WHERE site=? AND column_name=?
   AND pub_day>='2024-01-01' AND pub_day<='2025-12-31'
 GROUP BY ym ORDER BY ym;
```

**注意：缺月要补 0。** 某个月没有发文，画图时不能跳过，
否则曲线会把断档平滑掉，**看起来像发文平稳，其实是没有数据**。
这一点老师可能会问。

### 交付：`发文量按月.csv`

| 列 | 说明 |
|---|---|
| `ym` | 年月 `2024-01` |
| `count` | 篇数（**缺月补 0**） |
| `avg_chars` | 当月平均字数 |
| `joint_count` | 当月联合发文类篇数 |
| `note` | 异常说明（可选，如「本月无发文」） |

## 第二部分：主题演变（难点）

你要回答的问题是：**网信办在这个栏目里关注的问题，各年份之间有没有变？**

> ⚠️ **必须先确认样本覆盖了哪几年。** 抽样策略不同，年份覆盖完全不同：
> - `stratified`（按年份分层，默认）：2024 / 2025 / 2026 每年都有篇数 ✅
> - `recent`（最近 N 篇）：取最近 500 篇只覆盖 2025-03 之后，**2024 整年丢失** ❌
>
> 而且 **2026 年数据只到 10 月**，是**不完整的一年**。
> 拿它和完整年度直接比「发文量涨跌」会得出错误结论 ——
> 记得在报告里说明，或者只比 2024 vs 2025，把 2026 单独标注为「进行中」。

### 做法建议

1. **给每个月做主题聚类**（8-20 个主题为宜，不要太碎）
2. 主题词自己定，但必须**从文章标题+正文里真实出现过的词**来定，
   不许拍脑袋
3. 算每个主题的**月度占比**（不是绝对篇数 —— 否则发文多的月份会淹没一切）
4. 看哪些主题**上升 / 下降 / 稳定**

### 交付：`主题月度占比.csv`

| 列 | 说明 |
|---|---|
| `ym` | 年月 |
| `topic` | 主题名 |
| `count` | 当月该主题篇数 |
| `ratio` | 当月占比（0-1，当月全部篇数做分母） |
| `keywords` | 该主题的关键词，逗号分隔 |
| `sample_titles` | 该主题在当月的 2-3 个示例标题 |

## 第三部分：演变说明

### 交付：`README-时间轴与主题演变.md`

要写清楚：

1. 发文量的整体走势：**增长 / 平稳 / 波动**？有没有峰值月？
2. **哪些主题在上升、哪些在下降**，判断依据是什么
3. **有没有断档**（某几个月没发文）？什么情况导致的？
4. 你认为**最值得讲的一个发现**是什么
5. 所有统计用的 **SQL 原样贴出来**（数字要能被别人复现）

> ⚠️ 第 4 点特别重要。老师要求演示时「**讲一个发现**」，
> 你这份说明很可能就是那句话的素材。请给得**具体**，
> 比如「2025 下半年「未成年人」相关主题占比从 8% 升到 19%」，
> 而不要写「主题发生了变化」这种空话。

## 硬性要求

- 所有数字来自**实际查询**，不许估
- 缺月补 0，趋势图不能掩盖数据断档
- 主题必须从**真实出现的词**里提取，不能自己臆造分类
- 主题占比用**比例**，不要用绝对篇数（避免发文量掩盖主题变化）
- 时间序列**不要用饼图**
