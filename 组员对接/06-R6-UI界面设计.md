### 交付物 1：设计稿

至少出 **3 张**，用智能体画图能力直接生成：

### 交付物 2：`UI-设计规范.md`

必须写清楚：

1. **配色方案**
   - 背景 / 卡片 / 边框 / 正文 / 次要文字的具体色值（写 hex）
   - **四类实体（机构/政策/治理问题/措施）分别用什么颜色**
   - ⚠️ 四种颜色必须在深色背景下**都清晰可辨**，且色盲友好
2. **字体与字号层级**（标题/正文/注释各多大）
3. **间距规范**（卡片内边距、卡片间距、页面留白）
4. **图表配色**（柱状图/折线图/网络图的系列色）
5. **组件样式**：按钮、标签、表格、抽屉面板

### 交付物 3：`UI-改进意见.md`

针对**现有界面**提具体改进意见，每条写清楚：
- 现状问题是什么
- 改成什么样
- 为什么改

## 设计要求（这些是硬指标）

1. **深色主题**（现有网站是深色，保持一致；投影环境下深色更清晰）
2. **投影可读**：教室投影会缩小，**正文字号不要小于 14px**，
   图表轴标签**不能比正文还小**
3. **信息密度适中**：学术分析工具，不是营销落地页。
   别加无意义的渐变、插画、大留白
4. **可访问性**：正文与背景对比度足够；
   **不要只靠颜色区分信息**（图谱节点要同时用颜色 + 形状）
5. **网络图配色**：节点超过 8 个时，同色系会糊在一起，请给配色方案

## 不要做的事

- ❌ **不要用 React / Vue 组件代码代替设计稿**——我需要的是能照着实现的东西
- ✅ 如果写了组件原型或可交互 demo，**可以作为参考一并交**，
  它比静态效果图更能说明交互意图；但设计稿和规范本身必须有
- ❌ 不要重新设计整个网站信息架构——现有 5 个标签页是定好的
- ❌ 不要花哨。评委看的是「这个数据讲得清楚吗」，不是「这个页面好看吗」
- ❌ 不要交一张漂亮的效果图就说完了——**规范必须能让人照着实现**
