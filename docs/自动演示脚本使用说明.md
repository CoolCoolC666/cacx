# 自动演示脚本 · 使用说明

> 脚本：`autodemo.py`　　一键入口：`run-demo.bat`
> 手动版讲稿在 `docs/演示脚本-5分钟.md` —— **两份都要看**，
> 自动版负责「不出错」，手动版负责「答得好」。

## 一句话

现场不用手点，脚本自己走完 5 分钟：
打开网站 → 点两条关系回溯原文 → 讲一个发现 → 说局限，
全程带字幕、逐步截图，可选录屏。

## 怎么跑

**最简单**：双击 `run-demo.bat`

它会自己检查服务起没起，没起就拉起来（等约 30 秒），然后开始演示。

**命令行**（想调参数时）：

```
py -3 autodemo.py                    # 正常速度，约 4~5 分钟
py -3 autodemo.py --slow 1.5         # 放慢 1.5 倍，讲课用
py -3 autodemo.py --video            # 同时录屏，输出 webm
py -3 autodemo.py --headless         # 不弹窗，后台跑（自测用）
```

> 首次跑如果报「找不到浏览器」：
> `py -3 -m playwright install chromium`

## 产物在哪

`（测试）\演示产物\`

- `截图\01_*.png …` —— 每一步的截图，投屏留档、事后写报告都能用
- `*.webm` —— 录屏（仅 `--video` 时生成）

## 它是怎么保证「不出错」的

自动演示最危险的失败**不是报错**，是**看起来跑完了、其实关键那步没发生**。
所以脚本有一本**账本**：每一步实际观测到什么，都记下来，最后统一核账。

必须核的 11 项：

| 记账项 | 挡住的是什么 |
|---|---|
| 服务健康 | 服务没起就开始，页面全空 |
| 图已加载 | 图没画出来就开始讲 |
| 备选一证据 | 第一条边的证据条数 |
| 备选一有原文链接 | **老师点名要看的原文链接没有** |
| 备选一含两端主体 | 证据缺主体，等于白演 |
| 备选二证据 | 第二条边的证据条数 |
| 备选二有原文链接 | 第二条边的原文链接 |
| 字幕已渲染 | 观众看不到讲稿 |
| 字幕不遮挡证据 | 字幕把证据面板盖住了 |
| 时间轴已滚到位 | 讲发现时屏幕上没图 |
| 步数自洽 | 字幕显示 `[16/15]` 这类自相矛盾 |

任何一项没记到，**结尾核账就抛错停止**，不会硬撑着演完。

核账通过后会在 `（测试）\演示产物\核账结果.txt` 落一份凭据，
`main()` 再从磁盘复读一遍 —— 这样连「把核账代码删掉」这种手法也露馅
（自查拦不住自查被拆）。

### 为什么用「账本」而不是每步 if 一下

这看起来绕，其实是踩过坑才定的，而且**踩了两次**：

反向验证的第一版把变异打在 `if "打开原文" not in det:` 上 → **0/10 全没抓住**；
第二版打在 `book.mark(..., "打开原文" in det,)` 上 → **2/11**。

两次错在同一个地方：改的是**判定表达式**，把它改成永远为真。
而数据正常时判定**本来就该为真**，所以核账照样全绿、脚本照样 rc=0。

**把判定改坏，等于把探测器拆了 —— 那当然什么也测不到。**

正确方向是：**破坏被观测的事实，判定逻辑一个字不动。**
让证据真的没了、字幕真的不渲染、图真的滚出屏幕，
判定与核账就应当**发现**问题并拦住。跑不过 = 判定失灵，那才是真 bug。

账本第一次上线就抓到了两个真 bug：
1. 时间轴那步的图「找不到」—— 一查是我选择器写错了
   （时间轴用独立容器 `tl_vol`，不在 `#v_panel` 里）
2. 字幕放底部不只是遮挡，还会**拦截指针事件**
   （探针实测：底部字幕直接让导航按钮点不动，Playwright 一直 retry 到超时）

没有账本，这两处都是「以为没事，其实屏幕上不对」。

## 两个设计决定（值得知道）

**1. 它走的是真人点的同一条路径。**
点边调用的是网页自己的 `showEdgeEvidence(src, dst, relType)` ——
就是你手动点那条边时执行的同一个函数。
不直接调接口伪造面板，因为那样证明不了「页面上点得到」。

**2. 字幕放页面顶部，不放底部。**
这不是审美问题。关系图谱页的**证据面板正好在右下角**，
字幕放底部会把它整个盖住 —— 而那恰恰是老师要看的那块画面。

## 备选边的自动兜底

备选②（国家网信办 ↔ 网络数据安全风险评估办法）只有 3 条证据、节点度 6，
比备选① 脆。所以脚本里写死了兜底：备选② 打不开就**自动切**到
备选①同一批里的兜底边「中央网信办 ↔ 工业和信息化部」（65 条证据），
字幕会当场说明「这条换了一条」，演示不中断。

## 2026-10-13 事故复盘：`run-demo.bat` 一直**从来没跑起来过**

用户反馈「这个脚本我看不到运行」。查下来不是环境问题，是 `.bat` 本身**每次双击都秒死**，
所以窗口一闪就没、人根本看不到。此前所有验证都是直接 `py -3 autodemo.py`，
**从来没执行过这个 `.bat` 本身** —— 这就是它能带着两个致命 bug 一路活到今天的原因。

### 坑一：正文里一个非 ASCII 字节，整份脚本的解析就错位

`run-demo.bat` 第 48 行原本是：

```bat
echo [OK] Demo finished. Screenshots are in: （测试）\演示产物\截图
```

就为了打印一个带全角括号的中文目录名。后果不是「这行显示乱码」，而是**后面的行被拦腰截断**：

```
'l-auto' is not recognized      <- "full-auto" 被切开
'tr' is not recognized          <- "Add Python to PATH" 的尾巴
'..' is not recognized
命令语法不正确
```

`python -m autodemo.py` 那一行根本没执行。讽刺的是这个文件**第 4–7 行白纸黑字写着**
「本文件刻意只用 ASCII」，然后第 48 行就违反了它 —— 所以这条规则靠人记不住。

实测三种「修法」都不成立，别再试了：

| 写法 | 结果 |
|---|---|
| UTF-8 无 BOM + `chcp 65001` | **炸**（`启动cacx.bat` 原状就是这个） |
| UTF-8 **带 BOM** | **炸得更狠**，`@echo off` 都被 BOM 破坏 |
| 纯 ASCII | 通 |

修法：**文件名可以留中文**（那是给人双击的），**正文必须纯 ASCII**。
要输出中文，让 Python 去 `print`，别让 cmd 去 `echo`。

顺带把同病根的 `启动cacx.bat` / `同步最新文章.bat` 改成了纯 ASCII 转发壳
（逻辑统一到 ASCII 名的 `start-cacx.bat` / `sync-latest.bat`，不再两处各写一份）。

### 坑二：括号块里的 `%var%` 是**解析期**展开的

```bat
if errorlevel 1 (
    set /a tries=0
    :waitloop
    set /a tries+=1
    ...
    if %tries% lss 20 goto :waitloop    REM <-- tries 在这里恒为空
)
```

cmd 读到 `(` 就会把整个块**先读完再判断**，所以 `%tries%` 在块被解析时就展开了 ——
那时它还是上一轮的旧值（首次为空）。于是每次都报：

```
20 was unexpected at this time.
```

修法：把循环**挪出括号块**，改成平铺的 `:label` + `goto`，就没有「提前展开」这回事了。
（也可以 `setlocal enabledelayedexpansion` 用 `!tries!`，但平铺更难写错。）

### 防复发

```
py -3 （测试）\check-bat-ascii.py
```

扫项目根所有 `.bat`，有非 ASCII 就打印**行号 + 该行原文**并返回非 0。
`--inject` 是它自己的反向验证（确认探测器真能抓到）。
该闸已用真实事故行反向验证过：注入那行 → 精确报 `L52`、rc=1；还原 → rc=0。

## 常见问题

**Q：屏幕上有字幕，我还要自己讲吗？**
要。字幕是**提词器**，不是配音。它给你念稿，你照着讲、补充、答疑。
真要完全不讲话，字幕也能独立看懂，但那不像汇报，像放片子。

**Q：老师要求「现场点」，全自动会不会不合适？**
如果老师明确要求**你本人**操作，就用手动版讲稿
（`docs/演示脚本-5分钟.md`），里面标了每一步该点哪里。
自动版的价值在于：不练也能不出错，以及录一份留档。

**Q：能改讲稿吗？**
可以，`autodemo.py` 里搜 `cap(` 就能找到每一步。
改完注意两点：
- 步数是**自动算的**，不用手动同步
- 改完先 `py -3 autodemo.py --slow 0.2 --headless` 快速跑一遍

**Q：跑失败了怎么办？**
看打印的最后几行，那里写的是**核账没过的是哪几项**，以及当时观测到了什么。
修完再跑。

**Q：核账老是说某项不过，是不是该把它删掉？**
不要。核账项是保险丝，删掉它等于承认「这一步可以不发生」。
先查为什么没发生——账本抓出来的每一次，都是真 bug。
