## 四、残留与根因

1. **P2 只清了点名的 7 例，同类「活动/会议片段」仍有残留（值得下一轮处理）**
   禁表命中并清除了点名的 7 个坏例（的二十届四中全会 / 组织成员国元首理事会 / 重要思想理论研讨会 / 回归祖国25周年大会 / 互联网大会乌镇峰会 / 大数据产业博览会 / 中国网络文明大会），但 Top12 里仍能见到同一类问题：`协会召开第二届理事会`（45，第 5）、`第十一次全国代表大会`（11，第 12）；放宽到 Top50 还有 `安全治理新格局`、`周年文艺晚会`、`IPv6创新发展大会`、`第九届亚洲冬季运动会`、`全球数字经济大会`、`智能社会` 等。判断：**禁用表是白名单式的逐条封堵，没有从「机构名 vs 事件名」的形态规则上根治**，所以没被点名的活动片段照样进榜。建议后续把「含『召开/大会/运动会/周年/第…届/第…次』且无机构后缀」的结构化特征做成第二道通用闸门，而不是继续加长禁用表。

2. **P3 的性能收益随数据量放大，小样本上看不出**（如实记录，非问题）
   实测 500 篇 3.6s、2000 篇 13.3s、3000 篇 19.7s，约 6.6s/千篇。3000 篇 19.7s 与「改动后 ≈20s」一致；按同斜率外推 30000 篇 ≈3.3min，明显低于「改动前外推 ≈14min」。但 2000 篇（13.3s）与所给「改动前 ≈14s」几乎持平——**说明切词缓存的收益主要体现在更大规模/重复预览上**。本节**未对旧提交做 A/B 复测**（需回退到 3a1a431 之前并重启服务，超出本次只读验收范围），故「降低」是按所给基线对比得出的，非我实跑的旧版本对照。

3. **未写库已用数据自证**：预览抽取前后 `/api/graph/stats` 三值完全不变（entity_total 43927、relation_total 8499、rel_pairs 4191），确认「只预览未写库」。
