# cacx 启动说明 · 从解压到打开网站

> 面向拿到分发包的组员。**照着做即可，不需要懂 Python。**
> 读完全文你应该能：① 把网站跑起来 ② 看懂启动器替你做了什么 ③ 用对 8 个操作界面 ④ 出问题时自己定位。
>
> 版本：对应分发包 `cacx-分发版-20261016`｜最后核对：2026-10-16

---

## 一、最快路径：三步

1. **解压**到**不含空格与中文括号**的路径，例如 `D:\cacx`
   （路径里有特殊字符会让 `.bat` 报错，这是 Windows 的老毛病，不是本工具的 bug）
2. **双击 `启动cacx.bat`**（`start-cacx.bat` 效果完全相同，两个都保留只是为了你找得到）
3. 浏览器**自动打开** <http://127.0.0.1:8770/>

| 想做什么 | 怎么做 |
|---|---|
| 打开网站 | 浏览器访问 <http://127.0.0.1:8770/> |
| 停止服务 | **关掉那个黑色命令行窗口**（或窗口里按 Ctrl+C） |
| 再启动 | 重新双击 `启动cacx.bat` |
| 换端口 | 「设置」页改 `app.port`，保存后重启服务 |

**不需要装任何东西。** 这个包里自带了一套完整的 Python 运行时（在 `runtime\` 文件夹里），
解压后双击 `start-cacx.bat` 就能跑：**不需要装 Python、不需要管理员权限、不需要联网**。

这解决了三件事：

1. **机器上没有 Python** —— 用自带的 `runtime\python.exe`
2. **教室没网** —— 依赖已经预先装好在里面了，**首次启动不需要 `pip install`**
3. **每个人的 Python 版本不一样** ——  大家都用同一份已验证过的 3.12，
   不会出现「你这台机器上 import 报错、我的却正常」

> `runtime\` 文件夹是**随包的运行时**。它由 `（测试）\_build_portable_runtime.py`
> 从 python.org 的官方 embeddable 包构建，脚本随工程一起入库，可随时重建。
> 该脚本由 `runtime\` **不可用时**（通常是 zip 没解压全），启动器才会退回去
> 在本机找一个 Python ≥ 3.8 的来用。

⚠ **关窗口 = 关服务。** 服务不是后台程序，窗口关了网站就打不开了，这是正常现象不是崩溃。

## 二、`启动cacx.bat` 到底替你做了什么

这是最常被问的问题，所以逐项写清楚。**它一共只做 6 件事，全部在你看到网页之前完成。**

### ① 选一个解释器：先用自带的，其次才找本机的

启动器按这个顺序挑，**自带运行时永远优先**：

```
1. runtime\python.exe     ← 随包自带，3.12，装好了全部依赖
2. py -3                  ← 本机的 Python 启动器
3. python
4. python3
5. py -3.13 … py -3.8
```

取第一个能用的（≥ 3.8）。为什么自带排第一：

- 它是我们**实际测过**的那一份，所有人跑出来的东西完全一致；
- 不需要装、不需要管理员权限、不需要改 PATH；
- **首次启动不需要联网** —— 以前这一步是 `pip install`，教室没网就卡死。

为什么要试后面那几个入口（只在自带运行时缺失时才走）：`python` 并不等于「唯一那个 Python」。

- 装了新版但**没勾 PATH** 时，`where python` 可能只找得到旧版，而 `py -3` 照样能找到新版；
- `where python` 有可能命中 Microsoft Store 的**占位程序**（在
  `AppData\Local\Microsoft\WindowsApps\` 下），那根本不是解释器 —— 所以 `py -3` 排在最前面试。

全都找不到时才会停下，窗口里会**列出它到底找到了什么**（版本号 + 完整路径），
而不是只说一句「版本太老」。

### ② 检查依赖装好没有，并确认真的能 import

装完依赖不等于「程序能起来」：预编译包可能装上了却在当前平台 import 失败。
所以启动器会**再问一次解释器本身**：

```
python -c "import fastapi, uvicorn, requests, bs4, pyvis, jieba, networkx, scipy"
```

失败时它会把**真实的 ImportError 原样打出来**，而不是笼统的「安装失败」。

> 用自带运行时时这一步必然通过（依赖已经预装）；它真正兜住的是
> 「退回本机 Python」那条路上的失败。
> 历史上它值 3.10 的门槛：早期 `requirements.txt` 混进了 `mcp>=2.3`，
> 它在 3.9 上必然装不上，而当时给出的提示是「安装失败，请手动运行同一条命令」——
> 手动跑还是同样的失败，**一个把方向指错的死胡同**。

### ③ 检查可选的 MCP 功能在不在（缺了不算错）

`mcp` 是**唯一**要求 Python 3.10+ 的依赖，已经从 `requirements.txt` 拆到
`requirements-mcp.txt`。所以：

- 装了 → 窗口里打印一行「MCP server: available」，并给出运行命令；
- 没装 → 打印一段说明，告诉你这是**预期的**，网站照常启动，**不会中断**。

想启用：

```bat
python -m pip install -r requirements-mcp.txt
```

（这一条命令本身就需要 Python 3.10+。）

### ④ 检查依赖，装缺失的那些

**用自带运行时时这一步直接跳过** —— 8 个包已经预先装进 `runtime\` 里了：

`requests` `fastapi` `uvicorn` `beautifulsoup4` `jieba` `pyvis` `networkx` `scipy`

（`mcp` 不在其中 —— 它是需要 Python 3.10+ 的可选件，单独放在 `requirements-mcp.txt`。）

只有在退回用本机 Python 时，`pip install -r requirements.txt` 才真的会跑，
**而且那一步需要联网**。所以「首次启动请保持网络畅通」这句话，
**只对走了回退路径的人成立**。

**只有缺了才装**，装完即用，后续启动不再重复。
其中四个是网页功能需要的，装上才不出问题：

| 包 | 干什么 | 缺了会怎样 |
|---|---|---|
| `pyvis` | 图谱画布（自带 vis-network 内联，断网可用） | 图谱页画不出来 |
| `networkx` | 度 / 介数 / PageRank / 社区 / 连通块 | 图谱分析算不出来 |
| `scipy` | PageRank 的底层数值计算 | **能打开网站，但一进图谱分析就报错** |
| `jieba` | 中文分词 | 检索退化成标点切分 |

⚠ **`scipy` 这一条是踩过坑才补上的，值得单独说。**
`scipy` 以前没写进依赖，但它其实是**必需的**：`networkx` 的 `pagerank()`
在内部会无条件转到 `_pagerank_scipy`，而 `networkx` 自己**并不声明**
`numpy` / `scipy` 这两个依赖。于是会出现一种特别难查的状态：

> `pip install` 全部成功、48 项检查全绿、网站能打开，
> 但**只有「点进图谱分析」那一刻**才炸 —— 而且要等 4~5 分钟
> （先跑完整个分析流程才暴露），报的是 `No module named 'numpy'`。

开发机上恰好装了 scipy 才让这个问题隐身。
现在 `scipy` 已经写进 `requirements.txt`，并且加了一道**真跑小图 `analyze()`**
的冒烟检查（不是 import 一下就算过），所以缺它会在打包阶段就判红。

### ⑤ 检查数据库在不在（2026-10-15 新增）

`data\cacx.db` 不存在时会停下并说明原因，**让你选择**要不要带着空库继续。

为什么要专门加这一关：`Database` 打开库时会 `mkdir` + 建表，
而 SQLite 在文件不存在时会**自动创建一个空库**。
所以一旦压缩包没解压全（429 MB，很常见），网站会**照常打开、全是空的**，
不报任何错。你会以为工具坏了，其实只是数据没解压出来。

**报 `[ERROR] data\cacx.db is missing` 时怎么办**：回到上一步，重新完整解压一遍，
路径选短一些（`D:\cacx`），然后重新双击。

### ⑥ 检查端口 8770 有没有被占

被占用时它会告诉你占用进程的 PID，并问你要不要结束它重启：

- 选 **Y** → 结束旧进程，重新启动
- 选 **N** → 不动它，直接给你打开已经在跑的网站

### 然后才真正启动

执行 `python -m cacx serve`：加载配置 → 起 Web 服务 → 自动开浏览器。

⚠ `serve` 本身**不做任何额外检查**，它只负责把服务拉起来。
上面 6 步的检查全在 `.bat` 里，理由很实际——**出错时人还在看屏幕**，
这时候提示一句比让服务自己崩在后面好排查得多。

## 三、出问题了怎么查

按**症状**查，不要按错误信息猜：

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 双击后一闪就没 | 压缩包**没解压全**（`runtime\` 整个文件夹丢了） | 重新完整解压到短路径，例如 `D:\cacx`，并确认 `D:\cacx\runtime\python.exe` 存在 |
| 提示 “No usable Python” | 同上，且本机也没有可用的 Python | 同上；实在不行去 <https://www.python.org/downloads/> 装 3.12 并勾 “Add Python to PATH” |
| `[ERROR] data\cacx.db is missing` | 压缩包没解压全 | 重新完整解压到短路径 |
| `Port 8770 is already in use` | 上一次的服务还开着 | 选 Y 结束旧的重启；或选 N 直接用旧的 |
| 浏览器没自动打开 | 默认浏览器被改过 | 手动访问 <http://127.0.0.1:8770/> |
| 网站打开了但是**空的** | 数据库没加载 / 你打开的是空库 | 看 `/api/health` 返回的文章数；不是 0 就是数据没进来 |
| 图谱页画不出来 | 三个图谱包没装上 | 跑 `python -m pip install -r requirements.txt` 后重启 |
| 中文搜不出东西 | `jieba` 没装 | 同上 |
| 端口想换 | — | 「设置」页改 `app.port`，保存后重启服务 |

**一个万能自检**：浏览器打开 <http://127.0.0.1:8770/api/health>，
会返回一个 JSON，里面的文章数就是当前库里真实有多少篇。
**所有「页面看着不对」的问题，都先用它确认是数据问题还是显示问题。**

## 四、八个操作界面

顶部一排标签，共 8 个页面。默认停在「检索」。

### 1. 检索

**用来干什么**：在 28917 篇里按关键词找文章，找到了能看全文、能导出。

| 控件 | 作用 |
|---|---|
| 搜索框 | 空格分词。**≥3 字走 FTS5 索引**；1~2 字自动降级为全表扫描（慢但能出结果） |
| 站点 / 栏目 / 年份 | 逐级收窄 |
| 排序 | 按日期或按字数，正序倒序都行 |
| 日期 起 → 至 | 按发布日期筛 |
| 最少字数 | 滤掉太短的（常用来排掉列表页条目） |
| 隐藏正文未入库 | 默认勾上。列表页/栏目页不是文章，本来就没正文 |
| 只看正文未入库 | 想看「抓到了但正文没存下来」的条目时勾它，能跳原文、能指定补抓 |
| ↓ 导出 CSV / JSONL | 把当前结果导出来进 Excel 或写脚本 |

点标题看全文，命中词高亮。

### 2. 数据面板

**用来干什么**：一眼看清语料的形状，图表可直接放进论文。

**七张图两组**：

- 检索行为 4 张：按年分布 / 按月分布 / 栏目 Top12 / 行为
- 权责边界 3 张：治理问题分布 / 高频机构 / 联合发文月度趋势

**顶部筛选（改一处，七张图全跟着变）**：

| 控件 | 说明 |
|---|---|
| 站点 | 全部 / 中国网信办 / 浙江网信网 |
| 近 N 个月 | 6–120，默认 36 |
| 日期 起 ~ 止 | **优先级高于「近 N 个月」**：填了就按日期筛，两个都留空才回落到月份数 |

每张图右上角两个按钮：**⬇ 图**（PNG，2 倍分辨率，可直接放论文）、**⬇ 数据**（CSV，进 Excel 自己做图）。
面板区右上「**⬇ 面板 HTML**」把整个面板导出成一个独立 HTML 文件，**断网双击即开**，适合交作业。

⚠ **权责边界三张是关键词粗筛**（图上标了口径），拿来做核对可以，**别当精确统计引用**。
⚠ 按站点筛选时，行为图只统计 open / summarize——检索和导出是跨站行为，无法归属到某个站，界面上写明了，不是漏统计。

### 3. 样本配置器

**用来干什么**：按你自己的口径（栏目 + 时间窗 + 篇数上限）抽一批文章出来，导出 CSV 喂给分析。

支持按年分层抽样，抽样预览能**直接看到每年抽到几篇**，
导出的 CSV **文件带抽样口径页脚**（这份抽样是怎么来的，写在文件里，交给别人时不会失去语境）。

时间窗默认 `2024-01-01 ~ 2099-12-31`，与作业分析窗一致。

### 4. 关系图谱

**用来干什么**：看机构之间的协作网络，**点一条边能直接看到支撑它的原文句子和链接**。
这是老师要求「点每条边都能看到原文句子和来源链接」的落点，也是演示最该演的一页。

**筛选项**（改任何一项都会重算，图会变慢，属正常）：

| 控件 | 说明 |
|---|---|
| 口径 | 粗选（默认，不加形态闸门）/ 精选（滤掉「××协会第二届理事会」这类活动名机构） |
| 关系类型 | 勾选要显示哪几类关系 |
| 最小度数 / 最大度数 | 最常用。**最小度数调到 2 或 3，图会干净很多** |
| 聚焦 + 跳数 | 输入任一机构名，只看它周围 N 跳的协作对象（1–4） |
| 名称含 / 高亮 | 按关键词过滤 / 在图上标黄某个节点 |
| 站点 / 日期 | 按站点和月份筛 |

⚠ **三个口径别混着念，念错当场被问住**：

- 分析口径（min_degree=2）：**12162 节点 / 29069 边 / 886 个连通块**
- 网页画布默认实际绘制：**300 节点 / 2995 边**（权重截到前 300 个点，另有 11862 个低度数节点被折叠；**画布标题那行小字就是当前真值，念之前先看它**）
- 聚焦某机构 1 跳：中央网信办 **815 节点 / 4288 边**（换别的机构名数字会跟着变）

⚠ **第一次打开图谱页可能要等几十秒到几分钟**：它要现算全图的度 / 介数 / PageRank / 社区。
冷启动实测约 **270 秒**（介数是 O(V·E)，12162 节点 / 29069 边 ≈ 3.5 亿次运算，属固有成本）。
**耐心等，别连点刷新**——重复请求会排在同一个计算后面，越点越慢。

### 5. 🧪 分词实验室

**用来干什么**：改自己的分词词典，并当场看到「真的生效了」。两件事：

**① 挖掘新词**：无监督统计法（凝固度 + 邻字熵 + 可切分性）从语料挖候选词，
**由你勾选**才写进 jieba 用户词典，写完立即生效、**重启后仍在**。
候选是候选不是结论——统计只保证「大概率是词」，收不收由人定。
还有「🤖 AI 预勾选」：一键让 AI 把「像词」的那批先勾上，你只管改剩下的；
两步确认后才真调模型，**它只给建议、不写词典**，采纳仍然要你点按钮。⚠ 会消耗你自己的 API 配额，默认只预览不执行。

**② 试切分**：输入一句话，看它被切成什么样（回车即可）。

💡 **演示建议**：先试切「中央网信办深入开展清朗专项行动整治网络谣言」（会被切碎）
→ 采纳「清朗专项行动」「网络谣言」→ 再试一次（合并了）。
「自己改自己的词典」这件事比任何截图都有说服力。

### 6. ✦ AI 摘要

**用来干什么**：给文章生成摘要 / 标签，供检索和分析用。

顶栏显示生成情况（已生成 / 待生成 / 失败），页内可**在已生成的摘要、标题、标签里搜**，
失败清单实时对账并可清空、按错误分类。

⚠ **包内不含任何人的密钥。** 要用就在「设置」页填**你自己的** API 密钥。
⚠ 生成摘要消耗配额，程序默认「**只预览不执行**」，先预览再生成。
⚠ 密钥别发群里、别贴进代码、别提交到仓库。

### 7. ⇅ 数据同步

**用来干什么**：从两站公开列表接口拉新文章。**只读公开列表，不登录、不碰授权内容。**

| 控件 | 说明 |
|---|---|
| 站点 | 全部 / 中国网信办 / 浙江网信网 |
| 模式 | 增量（只补新增，**推荐**）/ 全量（重抓，慢） |
| 年份 | 可选，不选按设置页范围 |
| 开始同步 | 下面实时日志逐列滚动，顶部显示 列表/新增/失败/跳过 |
| 接口自检 | 诊断列表接口通不通 |
| 🩺 自检 + AI 根因 | 加一层，判断失败是不是 AI 摘要环节引起的 |

⚠ **「只盘点」模式只数条数不写库**，想先看有多少就选它。
⚠ 第一次点同步要等一会儿才有动静（列表接口本身慢），**别连点两下**——同时只能跑一个，第二次会被直接挡回。

### 8. ⚙ 设置

- **AI 供应商配置**：供应商 / 地址 / 模型 / 密钥。也可把其它 AI 工具的配置**粘贴到页面顶部自动导入**
- **站点设置**：新增/编辑自定义站点（写入 `config/sites.d/<code>.json`，不碰 `settings.json`）
- **共享服务**：`app.host` 改成 `0.0.0.0` 可供同组局域网访问
- **配置状态自检**：一眼看「配齐了没」（只告诉你有没有 key，不回显末四位）

## 五、进阶（用不到可以跳过）

### 和同组共享一台

- **同一台机器**：其他人直接访问 <http://127.0.0.1:8770/>
- **不同电脑**：设置页把 `app.host` 改成 `0.0.0.0`，同组用那台机器的**局域网 IP** 访问
  （在对方机器上跑 `ipconfig` 查 IPv4 地址）
- ⚠ **只在可信内网这么做，不要直接暴露到公网。**

### 让自己的 AI 智能体直接调用（26 个工具）

支持 MCP 的智能体（ChatGPT / Claude / Cursor / 豆包等）配置里加：

```json
{"mcpServers": {"cacx": {"command": "python",
    "args": ["-m", "cacx.mcp_server"], "cwd": "你解压的目录"}}}
```

⚠ `cacx_newwords_adopt` 会**往你的用户词典追加词**，默认 `confirm=false`，
必须显式传 `confirm=true` 才真正写入。

### 从零开始重建

包内已含全部数据，**不需要自己抓**。

- 想保留原始数据做对照 → **先复制一份** `data/cacx.db` 再改
- 想从零开始 → 删掉 `data/cacx.db`，然后 `python -m cacx sync`

## 六、一页速查

| 我想… | 就这么做 |
|---|---|
| 打开网站 | 双击 `启动cacx.bat` |
| 确认数据在不在 | <http://127.0.0.1:8770/api/health> 看文章数 |
| 关闭 | 关掉黑色命令行窗口 |
| 找文章 | 「检索」→ 关键词 → 导出 CSV |
| 做图表放论文 | 「数据面板」→ ⬇ 图（PNG）或 ⬇ 面板 HTML |
| 看机构协作 | 「关系图谱」→ 最小度数调 2~3 → 点边看原文 |
| 改分词词典 | 「分词实验室」→ 挖新词 → 勾选 → 试切分 |
| 更新到最新文章 | 「数据同步」→ 增量 → 开始同步 |
| 配 AI 功能 | 「设置」页填自己的密钥 |
| 换个端口 | 「设置」页改 `app.port` → 重启 |
