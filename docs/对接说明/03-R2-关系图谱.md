# 03 · R2 关系图谱

> 一句话：把 45 409 条实体和 8 801 条关系变成一张**可筛选、可回溯、可导出**的交互图，
> 并且保证零 CDN——教室断网也能打开。

## 1 这部分要解决的问题

评审方的网站要求里，关系图谱是核心展示物。要同时满足四件事：

1. 图要**交互**（点边看证据）
2. 图要**可筛选**（不然 1 633 个节点没法看）
3. 图要**能导出**（贴进 PPT / 报告）
4. 图要**零外部依赖**（教室投影时不一定有网）

第 4 条最容易踩：pyvis 默认从 CDN 拉 `vis-network.min.js`，
断网就是一个空白页，且**不报任何错**。

## 2 用户入口

网页顶部「关系图谱」页。上方一排筛选条，下方是图画出来的区域。

| 筛选控件 | 作用 | 对应实现 |
|---|---|---|
| 关系类型多选 | 只看 `joint_issue` / `issue` / `target` / `adopt` 中的若干类 | `build_graph(rel_types=...)` |
| 最低度数 | 只保留连接数 ≥ N 的节点 | `to_pyvis_nodes_edges(max_degree=...)` |
| 关键词 | 只保留名称含该词的节点及其邻居 | `keyword=` |
| 聚焦 + 跳数 | 聚焦某机构，看它 1 跳 / 2 跳的邻居 | `focus=` + `hop=` |
| 站点多选 | 只要 cac / zjwx 之一或两者 | `site=` |
| 日期区间 | 只看某段时间抽出的关系 | `date_from=` / `date_to=` |

## 3 与工具的接口面

### Web 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/graph/vis` | 返回图数据（节点 + 边 + 布局），参数与筛选条一一对应 |
| GET | `/api/graph/facets` | 返回可选的关系类型、站点、年份（筛选条的数据源） |
| GET | `/api/graph/analysis` | 图指标：度数中心性、介数中心性、社区发现、排名表 |
| GET | `/api/graph/evidence` | **点边回溯原文**（详见 [04](04-R3-机构合作网络与原文回溯.md)） |
| GET | `/api/graph/vislib.js` | 内联返回 pyvis 的 `vis-network` 运行时 |
| GET | `/api/graph/vislib.css` | 同上，样式 |
| GET | `/api/graph/stats` | 图规模概览 |
| GET | `/api/graph` | 旧版简化接口（保留兼容） |

**零 CDN 的实现**：`vislib.js` / `vislib.css` 由后端把本机 `lib/bindings/` 下的
文件内容原样吐出，前端 `<script src="/api/graph/vislib.js">`。
判据是**包内无 `http(s)` 外链**——相对路径 `lib/bindings/utils.js` 是合规的。

### 核心模块 `cacx/graph_analysis.py`

| 函数 | 作用 |
|---|---|
| `blocked_names` | 黑名单：剔除「大会主办」这类非机构片段进图 |
| `build_graph(rel_types=…)` | **在建图阶段**按关系类型 / 站点 / 日期过滤 |
| `crop_scope(…)` | 抽出「裁剪子图」逻辑，让分析与画图**共用同一张子图** |
| `analyze(…)` | 度数中心性、介数中心性、Louvain 社区发现（锁 `seed=42`） |
| `to_pyvis_nodes_edges(max_degree / keyword / focus / hop)` | 先裁子图，再按度数筛核心节点 |

依赖 `networkx`。Louvain **锁 seed=42**——不锁的话每次运行社区划分都不一样，
截图对不上、报告里写的社区数也没法复现。

## 4 数据流

```
entities + relations  （DB，只读）
        │
        ▼
  build_graph(rel_types, site, date_from, date_to)
  　⚠ 过滤在**建图阶段**做，不是画完再删
        │
        ▼
  crop_scope(focus, hop, keyword)
  　先裁出聚焦子图 —— 让分析指标和画出来的图是同一张
        │
        ▼
  to_pyvis_nodes_edges(max_degree)
  　在子图范围内再筛核心节点
        │
        ├──► /api/graph/vis ──► 前端 pyvis 渲染（vislib 由后端内联）
        └──► /api/graph/analysis ──► 度中心性 / 介数 / 社区 / 排名表
```

**导出**：`GET /api/export`（图谱页的「⬇ 导出」）会带上当前**所有**筛选条件，
生成的 HTML 内联 `vis-network`，双击即开、断网可用。

## 5 口径与分母

这里有三个真实的坑，都是「看起来对、其实错」：

1. **筛选后的指标必须在筛选后的范围内重算**。
   早期版本排名表跑的是**全图**，画的是**筛选后的子图**——
   中央网信办的介数在全图里是 0.194，聚焦 1 跳后是 0.8282，
   差了 4.3 倍。现在分析与画图共用 `crop_scope()` 的输出。
   **界面上两个数同时显示，并注明各自的范围。**

2. **度中心性 ≠ 权责边界，介数才是**。
   度数高只说明「认识的人多」，介数高才说明「别的机构都要经过它」。
   报告里论述权责边界时必须用介数，不能拿度数充数。

3. **日期边界要归一化**。
   早期 `date_from='2024'` 会生成 `BETWEEN '2024' AND '2024'` —— 恒为空集，
   界面表现为「筛了没反应」。现在统一归一化成 `2024-01-01` ~ `2024-12-31`。
   同时**整年被当成整月**的坑也修了：不再把 `2024` 当成一个月份。

## 6 已知局限（写进报告）

1. **115 个连通块**意味着图不是一张连通的网，而是一堆小团体。
   但要注意**别把连通块数当成质量的直接指标**：全量重抽之后，
   关系数从 1 311 涨到 8 801，图规模从 371 节点涨到 1 633 节点，
   连通块也从 30 涨到 115 —— 而最大连通块是 **1 296 个节点**，
   占了全图的 79%。也就是说新进来的关系大多在**同一个核心团**里，
   边长大边长小碎片。

   这是**实体碎片污染**在图上的投影：规则抽取把「中央网信办、
   农业农村部、商务部」这样的定语切出过碎片名，
   碎片名之间也共现，于是长尾上生出大量互不相干的小连通块。

   报告里不要把这张图说成「网信办的组织结构图」——
   它是「我们能观测到的合作结构」，覆盖率有限。
   写报告时建议给这三个数一起，缺一个就会把「图的样子」当成「现实的样子」：
   - **关系覆盖 1 257 / 4 513 篇 = 27.9%**（全部分析的分母是 4 513 篇有正文的文章）
   - **实体覆盖 3 901 / 4 513 篇 = 86.4%**
   - **最大连通块占比 79%**（核心有多集中）

   换句话说：多数文章能抽到机构，但只有约四分之一抽到了**机构之间的关系**。
   报告里该说的是「在能被观测到协作的那 27.9% 里，网信办居中协调」，
   而不是「网信办居中协调」。

2. **图谱是快照，不是动态**。图不会自己更新，重抽一次才变。

3. **布局由 pyvis 决定**，每次打开节点位置可能略有不同（随机化种子）。
   需要放进报告的图建议用「⬇ 导出」拿固定布局。

4. **不做社区发现结果的解读**。Louvain 分出的社区目前只是**列出来**，
   没有自动命名（用什么词概括这个社区）。报告若要讲「三大阵营」这类结论，
   必须人工看完社区成员后再写，不能直接拿算法输出当结论。

5. **筛选后的图会变小，但「变小的原因」有多种**（筛类型 / 筛度数 / 筛时间），
   界面上分开显示各项筛选后的关系数，避免「为什么少了一半」答不上来。
