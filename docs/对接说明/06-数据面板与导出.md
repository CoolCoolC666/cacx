# 06 · 数据面板与导出

> 一句话：面板是给报告配图的，「⬇ 面板 HTML」导出的独立文件
> 保证**双击即开、断网可用**，而且和屏幕上看到的**逐字符一致**。

## 1 这部分要解决的问题

网站本身是活的，但报告和 PPT 需要**能交出去的静态产物**。要求三条：

1. 导出的 HTML 独立可看（不能依赖服务在跑）
2. 零 CDN（教室没网就只有空白页，且**不报错**）
3. 屏幕上看到什么，导出就是什么

第 3 条是本项目反复栽跟头的地方——早期时间轴就是网页有、导出没有。

## 2 用户入口

「数据面板」页 → 右上角「⬇ 面板 HTML」。

导出的是一个完整 HTML 文件，内容包含：

- 按年分布、按月分布
- 栏目 Top 12
- 检索行为（近 N 天）—— 我们自己的操作记录
- 治理问题分布（对应报告的角色画像）
- 高频机构 Top 12（对应权责边界）
- 联合发文类文章月度趋势
- **时间轴三张图**（发文量 / 主题粗筛 / 主题 AI）

## 3 与工具的接口面

### Web 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/panel/snapshot` | **独立 HTML 面板**（本页的主产物） |
| GET | `/api/panel/export?which=…&format=csv` | 导出各组数据的 CSV |
| GET | `/api/trend` | 按月 / 按年分布 |
| GET | `/api/facets` | 栏目分布 |
| GET | `/api/events` | 检索行为 |
| GET | `/api/panel/problems` | 治理问题分布 |
| GET | `/api/panel/orgs` | 高频机构 |
| GET | `/api/panel/joint` | 联合发文趋势 |

> ⚠ 注意 `/api/trend` 与 `/api/facets` **没有 `panel/` 前缀**，
> 而 `/api/panel/problems`、`/api/panel/orgs`、`/api/panel/joint` 有。
> 这不是笔误，是历史演进留下的不一致——写接口表时以 `app.py` 为准。

`snapshot` 的参数：`site`、`months`（近 N 月）、`days`（检索行为窗口）、`top`。

### 纯手绘 SVG（`cacx/web/app.py`）

| 函数 | 用途 |
|---|---|
| `_svg_bars(rows, unit, w, h, label_every)` | 柱状图（按年 / 按月 / 栏目） |
| `_svg_stack(rows, keys, colors, unit, partial_last)` | 堆叠面积图（时间轴两张） |
| `_nice_max(v)` | Y 轴上限收成「好看的整数」且能被 4 整除 |
| `_tick_idx(n, every)` | 刻度下标，防末尾叠字 |
| `_PANEL_CSS` | 导出物专用的内联样式 |

**为什么手绘 SVG 而不用图表库**：

- ECharts / Chart.js 默认走 CDN，断网即空白
- 即便本地化，也要引一整个库进导出物
- 纯 SVG 生成的 HTML 文件，**双击就能看**，没有任何依赖

`_nice_max` 的存在理由值得一提：140 篇的样本会画出 `140 / 105 / 70 / 35` 这种刻度，
数学上没错，但一眼看上去像坏了，而且放大截图后更刺眼。
导出物是要贴进 PPT 的，这种细节很显眼。

## 4 数据流

```
 面板页面上方筛选（站点 / 近 N 个月）
        │
        ▼
  ┌── /api/trend         ──► trend_m / trend_y ──► _svg_bars ──┐
  ├── /api/facets        ──► 栏目 Top 12 ────────────────────┤
  ├── /api/events        ──► 检索行为 ──────────────────────┤
  ├── /api/panel/problems──► 治理问题分布 ──────────────────┤
  ├── /api/panel/orgs    ──► 高频机构 ──────────────────────┤
  ├── /api/panel/joint   ──► 联合发文趋势 ─────────────────┤
  └── /api/panel/timeline──► _timeline_impl（含三张 SVG）───┤
                                                            ▼
                                        内联 <style>{_PANEL_CSS}</style>
                                        全部 SVG 内联，无任何外链
                                                            ▼
                                      /api/panel/snapshot 返回整份 HTML
```

**同一份实现画两遍**这件事，是靠「只有一个函数」保证的：
网页与快照都调 `api_panel_*` 与 `_timeline_impl`，路由层是薄壳。
有测试断言快照里的 SVG 与接口返回的**逐字符相同**。

## 5 口径与分母

- 面板的**时间范围固定** `_PANEL_D0 = "2024-01-01"` ~ `_PANEL_D1 = "2099-12-31"`，
  与任务要求对齐。`2099` 是哨兵值，只用于让补零一路补到数据实际末月。
- 「检索行为」这张图画的是**我们自己的检索记录**（`events` 表，174 条），
  和前面三张「网信办角色画像」是两回事，界面上刻意分成两段并注明。
  报告里不要把它当成语料的一部分。
- 联合发文那张图画的是**占比**不是绝对篇数——
  发文多的月份会淹没趋势。

### 「浙江对照」这条选做要求

面板的站点筛选就是为它准备的：选「浙江网信网」时，
按月分布 / 栏目 / 治理问题 / 机构四张图全部变成浙江口径，
和两站合计版并排对比。

⚠ 这里修过一个真实的 bug：`/api/facets` 的栏目是**按站点分组再按篇数排序**的，
直接 `slice(0, 12)` 会让 CAC 库（比浙江大一个量级）吃满全部名额，
浙江一个栏目都不显示。这就是「浙江面板上根本没有浙江栏目」的真实原因，
不是数据缺失。现在每个站点各取 Top N。
但**选定单个站点时不能再除**——那是多站平分名额的场景。

## 6 已知局限（写进报告）

1. **导出是快照，不是活页面**。数据变了要重新导出。

2. **导出不含交互**。只有静态图和可折叠的数据表（`<details>`），
   不能筛选、不能点边回溯。要交互就得用网站。

3. **检索行为表只统计本机**。`events` 表记的是**这台机器上我们自己的操作**，
   不是全部使用者的使用情况。报告里不要把它说成「用户行为分析」。

4. **图表是手绘 SVG，不是专业图表**。优点是零依赖，缺点是
   没有 tooltip（只有 `<title>` 原生提示）、没有缩放、没有图例交互。

5. **时间轴的 AI 口径在导出里也是空态**。原因见
   [05](05-R4-时间轴与主题演变.md) 第 5 节——不是导出坏了，是本轮没跑模型。

6. **`_svg_stack` 的钳制是防御性的**。正常数据下 `mx ≥ 每个值`，钳制数学上冗余；
   它防的是「mx 被上游改错」这一类事故（SVG 越界不报错，只会把版面撑坏）。
   真正承担正确性的是坐标 `_clip`。
