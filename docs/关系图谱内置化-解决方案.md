## 一、先说清现状：哪些是**已有资产**，哪些是**真缺口**

### 已有（不要重造）

| 资产 | 位置 | 状态 |
|---|---|---|

| 写入/查询接口 | `/api/entities` `/api/relations` `/api/graph*` | ✅ 已实测 |

| 机构名候选挖掘 + 归并 | `textseg.mine_orgs` `normalize_orgs` | ✅ 已修过层级互斥/通用词/LCP 三个 bug |
| 治理问题词表 | `PROBLEM_TERMS`（10 类） | ✅ |
| 联合发文粗筛 | `joint_issue_trend()` | ✅ 关键词口径 |

### 真缺口（本次要补）

1. **没有抽取引擎**。表是空的，工具**只会读和写，不会抽**。数据全靠组员的智能体从外面灌 —— 这意味着「换个人做图谱」这节课就断链。
2. **前端没有图**。截图里「关系图谱」页是**列表 + 详情框**，不是网络图。老师要的是关系图谱，现在叫图谱但没图。
3. **没有关联分析**。即使灌了数据，也只有「谁和谁共现」，没有度数、介数、社区划分 —— 而这些才是「权责边界」的论据。
4. **分词只是「搜索用」**，没有做成可增长的分词系统（无新词发现、无用户词典、无领域词回流）。
5. jieba 是可选依赖，没装就退化成标点切分 —— **「内置分词系统」的前提是它变必需**。

## 二、目标（你那句构想的翻译）

> 让**关系**从「一张空表」变成**一个系统**：
> 工具自己会解析 → 解析结果自带原文证据 → 图谱是**画出来的** →
> 关联指标（度数/介数/社区）能支撑权责边界 → 分词在 AI 辅助下持续变准。

**关键设计原则**：解析必须**本地可复现**（同一份数据、同一份代码，永远抽出同样的结果）。
这是作业的属性——老师可能追问「你这个数怎么来的」，你必须能当场重跑给他看。
所以规则引擎是**主干**，AI 是**辅助**（质检与词典回流），不是反过来。

## 四、① 抽取引擎设计（`cacx/extract.py`，新建）

### 4.1 四类实体的判据（全部规则化，可解释）

| 类别 | 判据 | 精度预期 |
|---|---|---|
| **机构** | `textseg` 机构正则 + 后缀词（部/局/委/办/院/总局/中心/协会…）+ **并列切分** | 高 |
| **政策** | 《》书名号（最高精度）+ `…法/条例/办法/规定/意见/通知/规划/方案` 句式 | 很高 |
| **治理问题** | `PROBLEM_TERMS` 现有 10 类词表 + 同义词映射 | 中高 |
| **措施** | **动词模式**：`开展…专项行动` / `约谈` / `依法查处` / `下架` / `专项治理` / `责令整改` | 中 |

**并列切分是关键细节**。现在的归并层已经识别出「全国人大常委会国务院」是
两个机构连写，但抽取层还没做切分。加一条规则：

> 分隔符（`、`；与/和/及）出现，且两侧都命中机构后缀 → 切成两个独立实体。

这类句式在公文里极常见，不切的话机构名一污染，整张图谱就废。

### 4.2 关系的建边规则

| 关系 | 触发条件 | 方向 | MCP `rel_type` |
|---|---|---|---|
| `joint_issue` 联合发文 | **标题**含 联合/印发/会同/联发/共同，或正文出现「X部、Y局联合印发」 | 机构→机构 | `joint_issue` |
| `issue` 发布 | 出现「印发/发布/出台」+ 该政策 | 机构→政策 | `issue` |
| `target` 针对 | 出现「针对/整治/打击/治理/遏制」+ 该问题 | 机构→问题 | `target` |
| `adopt` 采取 | 出现「开展/采取/实施/启动」+ 该措施 | 机构→措施 | `adopt` |

**权重（`weight`）按共现强度分级**，这是「关联系统」的第一层：

| 级别 | 判据 | 权重 |
|---|---|---|
| 强 | 触发词出现在**同一句**内 | 3.0 |
| 中 | 同一自然段 | 2.0 |
| 弱 | 仅同篇出现 | 1.0 |

同句共现的联合发文基本可直接采信；仅同篇的边要标 `needs_review`。

### 4.3 硬约束（不可协商的三条）

1. **每条实体/关系必须有 `article_id`** —— 老师要求「点边看原文」，没出处的边是孤证。
2. **每条关系必须有 `evidence`**（原文句子，逐字照抄）—— 用字符偏移量从正文切，不用模型复述。
3. **正文 `chars < 200` 直接跳过**并计数 —— 这类文章抽出来全是噪声。

### 4.4 证据切句怎么实现（这是能不能「回溯」的关键）

不要让模型「总结一句原文」，那会失真，等于编造。做法：

1. 命中位置由规则给出（字符偏移 `start/end`），
2. 从原文取**所在句子**（按 `。！？；\n` 切句，找到包含该偏移的句子），
3. 存入 `evidence`，同时存 `evidence_start` 便于前端精确高亮。

这样保证 **evidence 一定是原文的连续片段**，可以程序化断言
「这段字符串在 `articles.content` 里 `in` 为真」——这就是验收标准。

## 五、② 关联分析（networkx，不自研算法）

用 `networkx` 把 `relations` 建成无向图，指标全部现成，**全部实测过**：

| 指标 | networkx 调用 | 在报告里怎么用 |
|---|---|---|
| **度** degree | `G.degree()` | 核心部门识别 |
| **加权度** strength | `G.degree(weight="weight")` | 「谁是真正的枢纽」（共现强度加总） |
| **介数** betweenness | `nx.betweenness_centrality(G)` | **权责边界的核心证据**：谁居中协调 |
| **PageRank** | `nx.pagerank(G)` | 影响力排序（与介数互补） |
| **社区** | `nx.community.louvain_communities(G, seed=42)` | 政策协同圈：「网信办+网信」/「网信办+公安」/「网信办+市场监管」 |
| **连通分量** | `nx.connected_components(G)` | 分几块各自为政 → 数据质量/结论边界 |

> `seed=42` 是刻意的：Louvain 有随机性，不固定种子的话
> 同一份数据两次跑出来的社区划分可能不同，**报告里的数字就不可复现了**。

⚠️ **度中心性 ≠ 权责边界**。介数和社区才是。这点要在报告里写清楚，
否则「网信办度数第一」会被老师追问「那它是不是什么都管」——答案是**不是，
它更多是协调枢纽**。这个区分本身就是权责分析的核心结论。

## 六、③ 前端：pyvis 内嵌（不自写力导向）

**为什么改用 pyvis**：力导向布局是从零写的话要几百行 JS，效果还不如现成的。
pyvis 直接给交互（缩放/拖拽/聚焦/工具提示），且**零 CDN 可行**（已实测，见第十一节）。

### 零 CDN 的做法（实测通过）

```
pyvis Network.write_html(notebook=False, local=True)
   ↓ 产物里含 4 条外链：
     cdnjs vis-network.min.css / .js
     jsdelivr bootstrap.min.css / bootstrap.bundle.min.js
   ↓ 全部替换成内联：
     vis-network.min.js  → 读 pyvis/lib/vis-9.1.2/vis-network.min.js（469 KB）
     vis-network.min.css → 读同目录 css（220 KB）
     bootstrap css/js    → 直接删（我们不用 bootstrap 布局，自己写样式）
   ↓ 产物：单文件，零外链，双击即开
```

> 页面里不引 bootstrap：容器宽度、网格、卡片样式全部自己写，
> 反正整站已经是自有 CSS 体系了，混进一套 bootstrap 反而难看。

### 节点视觉（四类实体，色盲友好）

| 类型 | 颜色 | 形状 |
|---|---|---|
| 机构 org | 蓝 `#4c8dff` | 圆 dot |
| 政策 policy | 紫 `#b48bff` | 方 square |
| 治理问题 problem | 红 `#ff6b6b` | 三角 triangle |
| 措施 measure | 绿 `#5ddc9a` | 菱形 diamond |

**不只靠颜色** —— 形状也区分，这是 R6 原来要求的硬指标，色盲同学能看懂。

节点大小 ∝ 度数，悬停显示「类型 · 度 N · 介数 M」。
点边 → 右侧 **原文句子 + 可点链接**（这块现有页面已经能用，接上数据即可）。

### 内嵌 vs 导出

- **网页内嵌**（已定）：日常用和演示都用它，点边直接弹证据面板
- 顺带提供「⬇ 导出单文件 HTML」按钮：同一套 pyvis 数据，
  导出成断网双击即开的版本，作为 PPT 附件/报告附录（后做，不阻塞主流程）

## 七、④ 分词系统（jieba 从「可选」变「内置 + 自学习」）

```
语料全文
   │
   ├─► jieba 精确模式 + 领域词典（现 70 条 → 目标 300 条）
   │
   ├─► 新词发现：互信息(MI) + 左右邻字熵(左右熵) 过滤
   │     （经典无词典新词发现算法，纯 Python，无需训练）
   │     → 产出「新词候选表 + MI/熵打分」
   │     → 人工或 AI 审定 → 回写 textseg 领域词典
   │
   └─► 用户词典：搜索页被搜过的词自动进候选 → 用过 2 次以上自动入词典
```

**AI 辅助的位置**：给新词候选做**批量判定**（「XX 是不是网信办领域的专有概念？」）
通过 MCP 工具 `cacx_put_dictionary(rows=[...])` 写入。一句话：
**AI 负责「判断」，规则负责「执行」**。

这样分词质量随使用变好，且每次改进都留痕在 `docs/` 里，
本身就是报告「方法与局限」那节能写的真东西。

## 八、⑤ AI 在整个系统里的正确位置

| 该用 AI | 不该用 AI |
|---|---|
| 判定新词是否为领域术语 | 抽取实体（要可复现） |
| 抽样质检、算准确率 | 建边（规则够用且可解释） |
| 复核归并中的 `needs_review` 组 | 分词（jieba 更快更可控） |
| 生成报告初稿、找「发现」 | —— |

**核心判据**：老师问「这个数怎么来的」，你必须能当场重跑。
规则引擎能，模型不能。（当然可以用 AI 生成提示词来辅助抽取，
但那属于「辅助」，不进主干，也不能作为唯一数据来源。）

## 十、风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 规则抽出来垃圾多 | 图谱不可信 | 只上**高置信**规则（政策/机构），措施类先标 `needs_review` 不进图 |
| 同页多次抽取产生重复 | 数据膨胀 | 复用现有 upsert 幂等逻辑（已验证同篇重复提交只累加 weight） |
| 全库 2.9 万篇太慢 | 现场演示卡 | **按需抽取**：默认只跑「样本口径」500 篇；全库后台增量 |
| 归并把不相关的机构并一起 | 结论失真 | 沿用已有三层硬约束 + 每组 `needs_review`/`merge_basis` 暴露给人复核 |
| 规则被老师质疑「太土」 | 印象分 | **主动讲**：这就是「可解释、可复现」的方法论，把准确率数据摆出来 |
