## 第一段：UI 走查（现在就能做）

把网站 7 个页签（检索 / 数据面板 / 样本配置器 / 关系图谱 / 设置 / AI 摘要 / 数据同步）
当一次「挑刺的用户」，交一份 `UI-走查意见.md`，每条三段式：

```
1. 现状问题：在哪个页签、什么操作下、看到了什么
   改成什么：具体、能照着做
   为什么改：和「课堂投影 / 交付成果 / 评审方追问」哪条有关
```

走查重点（按评审方的使用场景排的）：

- **投影可读性**：把浏览器缩放到 100%，投屏分辨率假设 1366×768——
  柱状图标签、表格小字、按钮文案能不能看清
- **面板七张图**：每张「⬇ 图」下载的 PNG 放进 PPT 是否清晰；
  「⬇ 面板 HTML」导出的文件**断网双击**打开，内容和屏幕上一致吗
  （这条是硬要求：交出去的就是导出的那份）
- **检索体验**：中文长句「整句精确」和「分词扩召回」两种模式的结果差别，
  高亮是否落在正确的词上
- **交互死角**：点了没反应的地方、报错提示看不懂的地方、
  弹窗/浮层盖住内容的地方（发现就截图标记）
- **文案**：口径说明是否写明白了（比如「关键词粗筛，各行相加会超过总数」）

> 参考基线（工程侧已修掉的，别重复提）：柱图横向溢出被遮挡、
> 超链接默认深蓝色不可读。如果你还看到类似**被遮挡/看不清**的东西，
> 说明有回归——截图 + 复现步骤，直接找维护者。

## 第二段：图谱验收（R1 数据回来之后做）

1. 随机点 **10 条**关系：每条都要出现原文句子 + 可点击链接，
   点开链接核对确实指向那篇文章。列成表交回。
2. 挑 **2 条最有故事的关系**（例如「中央网信办 →联合发文→ 某部委」
   和「某机构 →针对→ 网络谣言」），写成演示路径：
   从哪个页签进入、点什么、先说什么后说什么。**演示现场就点这两条。**
3. 截 **2 张清晰图**（图谱总览 + 点开一条关系后的证据面板），
   放进报告与 PPT 用。
4. `cacx_graph_stats()`（或图谱页顶部统计条）里 `no_evidence` 必须为 0 或接近 0，
   不为 0 就列清单退回给 R1 补证据。
